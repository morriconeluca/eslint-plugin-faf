# Contributing to eslint-plugin-faf

Thank you for contributing to `eslint-plugin-faf`! This document guides you through setting up the local development environment, project structure, writing rules, and releasing updates.

---

## Codebase Architecture

The project is structured to enforce strong type-safety, maintain clean boundaries, and follow strict linting patterns.

```
├── .changeset/               # Automatic packages version tracking configuration
├── .github/workflows/ci.yml  # GitHub Actions pipeline
├── .husky/                   # Git hooks (pre-commit lint-staged, commit-msg commitlint)
├── .vscode/                  # Shared VS Code workspaces settings & recommendations
├── __test__/                 # Architectural and graph fitness tests
├── src/                      # Plugin source code
│   ├── index.ts              # Entry point exposing rules and configs
│   └── rules/                # AST-based ESLint rules
│       ├── no-foo.ts         # Rule implementation
│       └── no-foo.spec.ts    # Rule tests
├── tsconfig.json             # Workspace-wide type checking compiler settings
├── tsconfig.build.json       # Production emit compiler settings
├── tsup.config.ts            # Tsup dual bundling (ESM + CJS) settings
├── eslint.config.ts          # Flat type-checked ESLint configuration
└── .prettierrc               # Prettier formatting configurations
```

### Dual Build System

ESLint plugins must support both CommonJS (CJS) and ES Modules (ESM) to run across diverse developer toolchains. We use **`tsup`** (powered by `esbuild`) to bundle and output both versions:

- **CommonJS** is compiled to `dist/index.cjs`.
- **ES Modules** is compiled to `dist/index.js`.
- **Typings** are generated into `dist/index.d.ts`.

### Dependency Fitness Function

Powered by `dependency-cruiser` inside `__test__/dependencies-graph/dependencies-graph.test.ts`, this test ensures:

- **Zero circular dependencies** between rules.
- **No orphan modules** (every rule must be exported by `src/index.ts`).
- **No incorrect internal imports** (e.g. source files referencing compiled `dist/` artifacts).

## Local Development Setup

### 1. Prerequisites

- Node.js (v20+ recommended)
- npm

### 2. Installation

Clone the repository and install the local dependencies:

```bash
git clone https://github.com/lucamorricone/eslint-plugin-faf.git
cd eslint-plugin-faf
npm install
```

---

## Development Scripts

- **Build**: Compiles rules into the CJS/ESM dual bundle inside the `dist/` directory.
  ```bash
  npm run build
  ```
- **Test**: Executes rule tests once.
  ```bash
  npm run test
  ```
- **Lint**: Performs type-checking (`tsc --noEmit`) and lints workspace files using ESLint.
  ```bash
  npm run lint
  ```
- **Lint Fix**: Resolves auto-fixable ESLint violations.
  ```bash
  npm run lint:fix
  ```
- **CI pipeline check**: Prepares build, verifies format, and runs rule tests.
  ```bash
  npm run ci
  ```

## Writing Custom Rules

ESLint rules analyze the AST (Abstract Syntax Tree) generated by parsers. We use `@typescript-eslint/utils` to write rules with full type safety.

### 1. Create the Rule file (`src/rules/my-rule.ts`)

```typescript
import { ESLintUtils } from '@typescript-eslint/utils';

export const ruleCreator = ESLintUtils.RuleCreator(
  (name) =>
    `https://github.com/lucamorricone/eslint-plugin-faf/blob/main/docs/rules/${name}.md`
);

export const myRule = ruleCreator({
  name: 'my-rule',
  meta: {
    type: 'suggestion',
    docs: {
      description: 'Describe what this rule does.',
    },
    schema: [], // Configuration schema
    messages: {
      ruleViolation: 'Triggered when a violation is found.',
    },
  },
  defaultOptions: [],
  create(context) {
    return {
      // AST Node visitors go here
    };
  },
});
```

### 2. Register the Rule (`src/index.ts`)

Add your rule to the `rules` export map:

```typescript
import { myRule } from './rules/my-rule.js';

export const rules = {
  'my-rule': myRule,
};
```

## Submitting Pull Requests & Release Flow

1. Commit message guidelines conform to **Conventional Commits** (validated by git hooks).
2. Before pushing your branch, run the local CI check: `npm run ci`.
3. Document your changes for version updates using Changesets:
   ```bash
   npx changeset
   ```
4. Push and open your PR.
